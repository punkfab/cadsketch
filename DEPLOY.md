# CADSketch — Shipping & Ops Runbook

Everything about getting this project online: the web app + landing page on
DigitalOcean, the custom domain, and iOS builds to TestFlight. Written because
this is easy to forget between releases.

## TL;DR — the two things you actually do

| Goal | Action |
|------|--------|
| Ship web app + landing | `git push` to `main` → CI builds & deploys automatically |
| Ship a new iOS TestFlight build | `git tag ios-vX.Y.Z && git push origin ios-vX.Y.Z` |

Everything below is detail and troubleshooting for when those don't "just work."

---

## What runs where

- **Geometry kernel** (`native/sketch_kernel.cpp`) — the one durable artifact. A
  flat C ABI behind `lib/ffi/sketch_kernel.dart` (conditional import):
  - native (desktop/iOS): compiled C++ via `dart:ffi`
  - web: same C++ compiled to **WASM** (emscripten) via `dart:js_interop`
- **Web app** — Flutter web, served at `https://cadsketch.ai/app/`
- **Landing page** — static HTML in `landing/`, served at `https://cadsketch.ai/`
- **iOS app** — Flutter iOS, kernel compiled in as a CocoaPod, → TestFlight

## Custom domain: cadsketch.ai (registrar = Namecheap)

Apex domain pointed at the DO app with **A records to DO's edge IPs**. We
deliberately do NOT use DO nameservers and do NOT use www.

- **Records on Namecheap (Advanced DNS → Host Records):**
  `@  A  162.159.140.98` and `@  A  172.66.0.96` (DO App Platform edge; AAAA
  `2a06:98c1:58::60`, `2606:4700:7::60` optional). No CNAME at apex, no URL Redirect.
- **SSL:** DO auto-issues + auto-renews a Let's Encrypt/Google Trust cert once
  the domain validates. Nothing to do.

### DNS gotchas that cost us hours (read before touching DNS)
1. **Namecheap "URL Redirect Record" silently breaks everything.** It points the
   apex at Namecheap's forwarder `192.64.119.121`, which 302-redirects the ACME
   challenge → the cert can NEVER issue. You **cannot delete the `192.64.119.121`
   A row directly** — it's regenerated by the URL Redirect record. Delete the
   **URL Redirect record itself** (its Type column says "URL Redirect").
2. **Leftover DO-managed DNS zone.** If a `doctl apps create` ever ran with a
   `zone:` in the spec, DO created a managed DNS zone for the domain. It persists
   and blocks ACME (DO validates against its own empty zone). Remove it:
   `doctl compute domain delete cadsketch.ai -f`. Keep `.do/app.yaml` domains
   WITHOUT a `zone:` field for registrar-managed DNS.
3. **Namecheap BasicDNS has no ALIAS/ANAME**, and apex CNAME isn't real DNS — so
   A records to the edge IPs are the only apex option here. (Caveat: those edge
   IPs are shared and can change; if the apex ever breaks, re-check them with
   `dig +short cadsketch-e2unu.ondigitalocean.app A`.)

### Diagnosing a stuck cert
- `curl -sI http://cadsketch.ai/.well-known/acme-challenge/probe` — if you see
  `X-Served-By: Namecheap URL Forward` or a 302, a redirect is hijacking the
  challenge (gotcha #1). Want `200` from `server: cloudflare` (DO's edge).
- `dig @$(dig +short NS cadsketch.ai | head -1) cadsketch.ai A` — authoritative
  answer, bypasses caching. Confirms what the registrar actually serves.
- `doctl apps get <APP_ID> -o json` → `.domains[].phase` (`ACTIVE` = done,
  `CONFIGURING` = still validating).

### One-time Apple-side setup (already done — here so you remember the shape)
TWO separate Apple websites, easy to confuse:
1. **developer.apple.com** = identifiers + signing.
   - Accept the **Program License Agreement** when prompted (Account Holder
     only). If the API returns `403 PLA_NOT_ACCEPTED`, this is why — nothing
     works until it's accepted.
   - Identifiers → ➕ → App IDs → **App** → explicit `cadsketcher.ai.app`. Leave
     all **capabilities unchecked** (add later if ever needed). App ID Prefix =
     Team ID.
2. **appstoreconnect.apple.com** = the app + TestFlight.
   - Apps → ➕ → **New App** (NOT "New App Bundle" — that's a *sales* bundle of
     multiple paid apps, unrelated). iOS, Name `CADSketch`, Bundle ID
     `cadsketcher.ai.app`, SKU is any unique internal string (never public).

### Cut a build
```
git tag ios-v0.1.1 && git push origin ios-v0.1.1
```
`.github/workflows/ios.yml` (macOS runner — bills ~10×, so builds are
intentional via tag) does: build native kernel + run tests → `flutter build ios`
(this runs `pod install`, which compiles the kernel pod) → archive with
**automatic cloud signing** (`-allowProvisioningUpdates` auto-mints the cert +
profile) → export & upload to TestFlight. Build number = Unix epoch (always
increasing). ~15–20 min.

### Get a build onto your iPad (every new tester)
1. App Store Connect → CadSketcher AI → **TestFlight** tab (not Distribution).
2. **Export compliance:** if a build shows "Missing Compliance," open it and
   answer the encryption question **No**. (Avoid this forever by adding
   `ITSAppUsesNonExemptEncryption = false` to `ios/Runner/Info.plist`.)
3. **Internal Testing** → create a group → add your **Apple ID as a tester**
   (you are NOT auto-added just by being account holder). Internal groups
   **automatically get every build** — you do NOT (and cannot) assign a specific
   build to an internal group; that only applies to *external* groups.
4. On the iPad: install the **TestFlight** app, sign in with the **same Apple ID
   you added as a tester**, pull to refresh. ~5–10 min to propagate.
- **External testers** (people not on your team) need an External group AND a
  one-time **Beta App Review** per build before they can install.

### iOS gotchas
- `flutter test` runs on the Dart VM via the FFI path, so CI must build the
  native kernel (`build_native.sh`, needs cmake+ninja) BEFORE `flutter test` —
  otherwise 33 tests fail with a missing-library error. Done in both
  `web.yml` and `ios.yml`.
- **Flutter never runs `pod install` for this app** — it only runs CocoaPods when
  there are plugin *packages*, and this app is pure FFI (zero plugins). So the
  hand-written Podfile + kernel pod were silently ignored on every build (no
  `ios/Podfile.lock`, no `ios/Pods/`), and the kernel was never compiled. CI must
  run it explicitly: `flutter build ios --config-only --release --no-codesign`
  (writes `Generated.xcconfig`) then `cd ios && pod install`, and archive the
  **`.xcworkspace`** (not the bare `.xcodeproj`). Done in `ios.yml`.
- The kernel pod (`sketch_kernel.podspec`, at the repo ROOT so `native/*.cpp` is
  inside the pod root) builds as a static `libsketch_kernel.a`. No
  `use_frameworks!` (keeps pods static so the `.a` exists).
- **"Failed to lookup symbol sk_version" at runtime (build succeeds, app runs):**
  `DynamicLibrary.process()` → `dlsym(RTLD_DEFAULT, …)` reads the executable's
  **dyld export trie**. Getting `sk_*` in there needs THREE settings on the
  Runner target (all in the Podfile `post_install`), governing three stages — and
  ALL THREE are required:
  1. `-force_load "${PODS_CONFIGURATION_BUILD_DIR}/sketch_kernel/libsketch_kernel.a"`
     in `OTHER_LDFLAGS` — the `sk_*` code is only referenced from Dart at runtime,
     so without this the linker dead-strips the whole archive.
  2. `EXPORTED_SYMBOLS_FILE = $(SRCROOT)/sk_exported_symbols.txt` — fed to the
     linker as `-exported_symbols_list`, putting the 15 `sk_*` symbols in the
     link-time export trie (iOS executables export nothing by default).
  3. `STRIP_STYLE = non-global` — the archive's install action runs `strip`
     (`STRIP_INSTALLED_PRODUCT=YES`), which with the default style removes ALL
     global symbols and rebuilds the trie WITHOUT `sk_*`, undoing #2.
     `EXPORTED_SYMBOLS_FILE` is fed only to ld, **not** to strip, so the link can
     look perfect while the shipped binary loses the exports. `non-global`
     (`strip -x`) keeps externals.
  Earlier wrong guesses: `-Wl,-export_dynamic`, and the raw
  `-Wl,-exported_symbols_list` flag (works for the link, strip undoes it).
- **Debug this cert-free, and inspect the ARCHIVE binary.** `flutter build ios
  --release --no-codesign` does NOT run the install-action strip → false green.
  `ios-diagnose.yml` (manual `workflow_dispatch`, no certs) runs a real unsigned
  `xcodebuild archive` (`CODE_SIGNING_ALLOWED=NO`) and dumps
  `dyld_info -exports` on `build/Runner.xcarchive/.../Runner.app/Runner` — the
  faithful check. Use it instead of burning signed builds (each signed CI build
  mints a throwaway dev cert and you'll hit Apple's cert cap).

## Quick API checks (using the .p8)

`/tmp/asc.py "<path>"` mints a JWT and GETs the path. Examples:
- Apps: `/v1/apps?limit=200`
- A build's state: `/v1/builds?filter[app]=6783180350&include=buildBetaDetail`
  (`processingState`, `usesNonExemptEncryption`, `internalBuildState`)
- Beta groups: `/v1/betaGroups?filter[app]=6783180350&include=betaTesters`
